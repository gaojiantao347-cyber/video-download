# 后端功能文档 后续规划

版本：V2.1  
日期：2026-04-28

## 1. 后续系统定位

MVP 阶段先完成单链接下载闭环。后续阶段的目标是演进为一个“大而全的视频平台爬虫软件”。

后端长期目标：

```text
多平台适配 -> 多类型采集源 -> 爬虫任务调度 -> 内容解析 -> 去水印处理 -> 去重入库 -> 文件下载 -> 内容资产管理 -> 统计分析 -> 运维监控
```

## 2. 总体架构能力

| 能力域       | 说明                                                           |
| ------------ | -------------------------------------------------------------- |
| 平台适配层   | 为抖音、快手、B 站、小红书、微博、西瓜视频等平台提供独立适配器 |
| 采集源管理   | 管理单视频、作者主页、合集、话题、关键词、搜索页等采集入口     |
| 爬虫任务调度 | 支持一次性任务、周期任务、增量任务、失败重试                   |
| 解析引擎     | 解析视频、作者、封面、发布时间、标签、统计数据等元信息         |
| 去水印引擎   | 解析无水印资源、选择处理策略、记录处理结果                     |
| 下载引擎     | 支持队列下载、并发限制、断点续传、文件校验                     |
| 去重系统     | 基于平台 ID、视频 URL、内容指纹等方式去重                      |
| 内容库       | 保存视频、作者、平台、标签、文件、任务关系                     |
| 文件存储     | 管理本地文件、目录规则、清理策略、文件一致性                   |
| 监控告警     | 监控任务失败率、平台解析异常、磁盘空间、队列积压               |
| 配置中心     | 管理平台配置、并发配置、限速配置、存储配置、去水印策略         |
| 审计日志     | 记录任务操作、配置变更、文件删除、授权变更                     |

## 3. 平台支持规划

| 平台     | 单视频 | 作者主页 | 合集/列表 | 话题/标签 | 关键词搜索 |     去水印 | 优先级 |
| -------- | -----: | -------: | --------: | --------: | ---------: | ---------: | -----: |
| 抖音     |     是 |       是 |        是 |        是 |         是 |         是 |     P1 |
| 快手     |     是 |       是 |        是 |        是 |         是 |         是 |     P1 |
| B 站     |     是 |       是 |        是 |        是 |         是 | 视资源情况 |     P2 |
| 微博视频 |     是 |       是 |      可选 |      可选 |         是 | 视资源情况 |     P2 |
| 西瓜视频 |     是 |       是 |        是 |      可选 |         是 | 视资源情况 |     P2 |
| 小红书   |     是 |       是 |      可选 |        是 |         是 | 视资源情况 |     P3 |

原则：

- 每个平台必须独立适配，不能把平台逻辑写死在主流程里。
- 平台能力必须可开关，某个平台异常时不能影响其他平台。
- 每个平台都要有样例链接、解析测试、失败错误码。
- 去水印能力必须按平台声明支持级别，不允许假装所有平台都稳定可用。

## 7. 去水印处理体系

### 7.1 去水印策略分层

| 层级 | 策略           | 说明                                     | 推荐优先级 |
| ---- | -------------- | ---------------------------------------- | ---------: |
| L1   | 无水印资源地址 | 平台解析器直接获取无水印视频地址         |       最高 |
| L2   | 转封装处理     | 对已获取媒体流进行封装转换，不做画面修复 |         高 |
| L3   | 画面级处理     | 裁剪、模糊、覆盖、AI 修复等后处理        |         低 |

建议：

- P1 阶段只稳定做 L1。
- L2 依赖 FFmpeg，可作为后续可选能力。
- L3 成本高、效果不可控，只有明确需要时再做。

### 7.2 去水印状态

| 状态            | 说明                 |
| --------------- | -------------------- |
| `NOT_REQUESTED` | 未请求去水印         |
| `REMOVED`       | 已获得无水印版本     |
| `UNAVAILABLE`   | 未找到可用无水印资源 |
| `FALLBACK`      | 已降级普通下载       |
| `PROCESSING`    | 正在进行媒体后处理   |
| `FAILED`        | 去水印失败           |

### 7.3 去水印策略记录

| 字段           | 说明             |
| -------------- | ---------------- |
| `strategy`     | 采用的去水印策略 |
| `inputFileId`  | 输入文件 ID      |
| `outputFileId` | 输出文件 ID      |
| `startedAt`    | 开始时间         |
| `finishedAt`   | 完成时间         |
| `errorMessage` | 失败原因         |

### 7.4 技术实现建议

| 能力            | 技术建议                                   |
| --------------- | ------------------------------------------ |
| 无水印 URL 解析 | 平台适配器内部实现                         |
| 转封装          | FFmpeg sidecar                             |
| 裁剪/模糊       | FFmpeg filter，可选                        |
| AI 修复         | 暂不建议，模型体积大、速度慢、桌面端成本高 |

## 8. 去重策略

| 策略             | 说明                                   |
| ---------------- | -------------------------------------- |
| 平台视频 ID 去重 | 同一平台同一视频 ID 只保留一条         |
| 来源 URL 去重    | 相同落地页 URL 不重复入库              |
| 文件哈希去重     | 下载后基于文件哈希检测重复文件         |
| 无水印文件哈希   | 无水印版本单独记录文件哈希             |
| 标题作者弱去重   | 辅助识别搬运或重复内容，不作为唯一判断 |

去重结果：

| 状态         | 说明               |
| ------------ | ------------------ |
| `NEW`        | 新内容             |
| `DUPLICATED` | 已存在内容         |
| `UPDATED`    | 已存在但元数据更新 |
| `SKIPPED`    | 按规则跳过         |

## 9. 下载与文件系统

| 功能           | 说明                                 |
| -------------- | ------------------------------------ |
| 下载队列       | 将视频下载和内容采集解耦             |
| 并发下载       | 全局和平台维度限制并发               |
| 断点续传       | 支持可续传资源的断点续传             |
| 文件校验       | 下载后校验大小、哈希、文件可读性     |
| 文件命名       | 按平台、作者、标题、发布时间生成路径 |
| 去水印版本管理 | 普通版本和无水印版本可以分别记录     |
| 文件清理       | 按策略清理过期文件                   |
| 文件修复       | 数据库有记录但文件丢失时可重新下载   |

推荐目录规则：

```text
downloads/{platform}/{authorName}/{publishDate}/{title}-{videoId}.mp4
downloads/{platform}/{authorName}/{publishDate}/{title}-{videoId}_no_watermark.mp4
```

## 10. 数据库规划

后续做大而全爬虫软件，建议使用关系型数据库。

| 表                          | 说明                                   |
| --------------------------- | -------------------------------------- |
| `platform`                  | 平台配置                               |
| `crawl_source`              | 采集源                                 |
| `crawl_task`                | 爬虫任务                               |
| `crawl_task_log`            | 任务日志                               |
| `video`                     | 视频元数据                             |
| `author`                    | 作者元数据                             |
| `video_file`                | 视频文件记录，区分普通版本和无水印版本 |
| `watermark_processing_task` | 去水印处理任务                         |
| `tag`                       | 标签                                   |
| `video_tag`                 | 视频标签关系                           |
| `download_task`             | 下载任务                               |
| `system_config`             | 系统配置                               |
| `auth_account`              | 用户主动授权的平台账号                 |
| `audit_log`                 | 审计日志                               |

技术建议：

- 单机早期可以 SQLite。
- 正式多任务场景建议 MySQL 或 PostgreSQL。
- 不要在没有瓶颈前引入分布式数据库。

## 13. 合规与安全边界

后续可以做大而全，但边界必须写进系统设计。

| 边界               | 说明                                             |
| ------------------ | ------------------------------------------------ |
| 仅处理用户有权内容 | 去水印只面向用户有权下载和使用的内容             |
| 不绕过 DRM         | 不下载 DRM、付费、会员限制内容                   |
| 不绕过私密权限     | 不采集私密、不可公开访问内容                     |
| 不破解验证码       | 不提供验证码破解或规避能力                       |
| 不窃取 Cookie      | 不从浏览器或本地环境偷取登录态                   |
| 授权账号显式添加   | 账号或凭证必须由用户主动配置                     |
| 请求限速           | 避免对平台造成异常压力                           |
| 审计日志           | 记录高风险操作、配置变更、去水印批处理和文件删除 |
