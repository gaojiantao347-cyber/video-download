## 1. 开发目标

前端第一阶段目标不是做完整管理后台，而是交付一个 Windows/macOS 桌面端 MVP：

```text
用户打开 Tauri 桌面应用
  -> Vue 前端检测 Rust facade 健康状态
  -> 用户粘贴抖音/快手公开视频链接
  -> 创建下载任务
  -> Rust 调用 Python vd-engine / yt-dlp 下载
  -> 展示下载进度、去水印状态和失败原因
  -> 下载完成后打开文件或所在目录
```

MVP 必须坚持简单：只做单链接下载闭环，不做批量下载、账号授权、复杂采集源、内容库大后台、WebSocket 实时推送。

正式通信链路以 Tauri command 调用 Rust `engine_rpc` facade 为准，不把 Vue 页面直接绑定到 localhost HTTP API。

## 3. 第一阶段：工程初始化与桌面骨架 (第 1 周)

**目标**：建立 Tauri + Vue 3 + TypeScript 工程，形成可运行的桌面窗口和基础规范。

| 工作项         | 交付物                                        | 关键要求                                       |
| -------------- | --------------------------------------------- | ---------------------------------------------- |
| 初始化前端工程 | `apps/desktop-ui`                             | Vue 3 + TypeScript + Vite + npm                |
| 初始化 Tauri   | `apps/desktop-ui/src-tauri`                   | Tauri 2；只开放必要权限                        |
| 接入 UI 基础库 | Element Plus                                  | 先用标准组件，不自造 UI 轮子                   |
| 接入路由       | Vue Router                                    | MVP 可只有下载页和设置页                       |
| 接入状态管理   | Pinia                                         | 只放跨页面状态，不把所有局部状态塞 store       |
| 接入异步查询   | TanStack Query for Vue                        | 任务轮询、引擎健康检查、配置查询               |
| 样式体系       | `assets/styles/variables.scss`、`global.scss` | 使用 Element Plus 默认蓝 `#409EFF`；统一状态色 |
| 代码规范       | ESLint、Prettier、TypeScript strict           | 禁止 `any` 泛滥；DTO 必须有类型                |
| 主布局         | `MainLayout.vue`                              | 左侧栏可先简化；顶部展示引擎状态               |
| 自定义标题栏   | `AppTitleBar.vue`                             | 支持拖拽、最小化、最大化、关闭                 |

MVP 初始路由建议：

| 路由        | 页面           | 阶段     |
| ----------- | -------------- | -------- |
| `/download` | 单链接下载页   | MVP      |
| `/settings` | 基础设置页     | MVP      |
| `/about`    | 版本和引擎信息 | MVP 可选 |

## 4. 第二阶段：Tauri 与本地下载引擎通信 (第 2 周)

**目标**：打通 Vue -> Tauri command -> Rust `engine_rpc` facade -> Python 下载引擎的正式调用链。

| 工作项           | 交付物                            | 关键要求                                       |
| ---------------- | --------------------------------- | ---------------------------------------------- |
| 引擎客户端封装   | `api/engineClient.ts`             | 页面禁止直接写 `invoke` 细节                   |
| 下载 API 封装    | `api/downloadApi.ts`              | 封装 `download.createTask`、`download.getTask` |
| 设置 API 封装    | `api/settingsApi.ts`              | 查询/保存下载目录、去水印默认配置              |
| 引擎状态 Store   | `stores/engineStore.ts`           | `starting`、`ready`、`disconnected`、`error`   |
| 健康检查查询     | `queries/useEngineHealth.ts`      | 周期查询 `engine.healthCheck`                  |
| RPC 错误处理     | `api/errorMapper.ts`              | 后端错误码映射为前端文案                       |
| 下载引擎 facade | `src-tauri/src/engine_process.rs` | 健康检查、任务状态、Python CLI 启动、异常提示  |
| RPC 转发命令     | `src-tauri/src/rpc_bridge.rs`     | Tauri 负责转发，不写业务规则                   |

正式调用方向：

```text
Vue 页面
  -> downloadApi.createTask()
  -> engineClient.call('download.createTask', params)
  -> Tauri invoke('engine_rpc')
  -> Rust EngineProcessManager
  -> Python vd-engine / yt-dlp
```

前端不直接访问本地配置文件，不直接管理 Python 下载进程，不直接解析平台页面。

## 6. 第四阶段：任务轮询、状态展示与重试 (第 4 周)

**目标**：让任务状态稳定刷新，失败可理解，重试可控。

| 工作项           | 交付物                                           | 关键要求                                        |
| ---------------- | ------------------------------------------------ | ----------------------------------------------- |
| 任务查询 Hook    | `queries/useDownloadTask.ts`                     | 任务运行中每 1 秒轮询，结束后停止               |
| 任务列表本地缓存 | `features/download/taskSessionStore.ts` 或 Pinia | MVP 只保留当前会话最近任务，不做复杂历史库      |
| 重试失败任务     | `retryDownloadTask`                              | 使用原链接重新创建任务，保留旧失败信息          |
| 状态文案映射     | `taskStatusMap.ts`                               | 状态、颜色、图标、说明统一维护                  |
| 错误码文案映射   | `errorMessageMap.ts`                             | 与 `contracts/errors` 对齐                      |
| 去水印状态展示   | `WatermarkStatusTag.vue`                         | `REMOVED`、`UNAVAILABLE`、`FALLBACK` 等明确提示 |
| 全局消息         | `ElMessage` / `ElNotification`                   | 成功、失败、引擎断开时给明确反馈                |

状态展示规则：

| 后端状态      | 前端文案         | 前端表现                |
| ------------- | ---------------- | ----------------------- |
| `PENDING`     | 等待下载         | 灰色标签                |
| `DOWNLOADING` | 正在下载         | 进度条                  |
| `SUCCESS`     | 下载完成         | 成功标签 + 文件操作按钮 |
| `FAILED`      | 下载失败         | 错误提示 + 重试按钮     |

错误码最低覆盖：

| 错误码                         | 前端文案方向                           |
| ------------------------------ | -------------------------------------- |
| `URL_EMPTY`                    | 请输入视频分享链接                     |
| `URL_INVALID`                  | 请输入合法的 http/https 链接           |
| `PLATFORM_NOT_SUPPORTED`       | 当前仅支持抖音、快手公开视频链接       |
| `URL_EXPIRED`                  | 视频链接可能已失效                     |
| `PARSE_FAILED`                 | 视频解析失败，请检查链接是否公开可访问 |
| `WATERMARK_REMOVE_UNAVAILABLE` | 未找到可用无水印资源                   |
| `DOWNLOAD_FAILED`              | 视频下载失败，请稍后重试               |
| `FILE_TOO_LARGE`               | 视频文件超过大小限制                   |
| `FILE_NOT_FOUND`               | 文件不存在或已被清理                   |
| `STORAGE_ERROR`                | 本地存储异常，请检查下载目录权限       |

## 7. 第五阶段：设置页与桌面端能力 (第 5 周)

**目标**：补齐桌面软件必须有的基础设置和系统交互。

高风险操作确认：

| 操作             | 要求                             |
| ---------------- | -------------------------------- |

| 打开外部文件路径 | 只使用后端返回的安全文件路径     |
| 清空当前会话任务 | 二次确认，MVP 可选               |

## 8. 第六阶段：构建、打包与前后端集成 (第 6 周)

**目标**：前端能接入后端 sidecar 产物，完成桌面开发和打包链路。

| 工作项       | 交付物                                | 关键要求                                         |
| ------------ | ------------------------------------- | ------------------------------------------------ |
| 开发命令     | `npm run dev`、`npm run tauri:dev`          | 本地开发可启动桌面窗口                           |
| 前端构建     | `npm run build`                       | 生成 Vue 静态资源                                |
| Tauri 权限   | `src-tauri/capabilities/default.json` | 最小权限；只允许必要 sidecar、dialog、shell 能力 |
| 后端产物接入 | `src-tauri/binaries/`                 | 接入 Python `vd-engine(.exe)` sidecar            |
| 打包配置     | `tauri.conf.json`                     | externalBin、应用图标、窗口配置                  |
| 构建脚本衔接 | `scripts/package-desktop.sh`          | 前端构建依赖后端 `copy-sidecar` 输出             |
| 平台验证     | Windows/macOS                         | 分别验证启动、下载目录、文件打开                 |

构建流：

```text
后端准备 vd-engine(.exe)
  -> scripts/copy-sidecar.sh 复制到 src-tauri/binaries/
  -> npm run build
  -> npm run tauri:build
  -> 输出 Windows/macOS 安装包
```

## 11. 前端开发原则

| 原则     | 具体要求                                                          |
| -------- | ----------------------------------------------------------------- |
| KISS     | MVP 只做单链接下载页和基础设置页，不搭空后台                      |
| YAGNI    | 不提前实现批量、内容库、图表、账号授权等后期页面                  |
| DRY      | 状态文案、错误码文案、DTO 类型集中维护，页面不重复写映射          |
| SOLID    | 页面负责组合，业务逻辑下沉到 feature、api、query、store           |
| 类型优先 | TypeScript strict；接口响应必须有明确类型                         |
| API 集中 | 页面禁止直接调用 Tauri invoke，统一经过 `api/*.ts`                |
| 桌面边界 | Vue 不直接启动 Python 进程，不直接读本地配置文件，不直接操作任意文件路径 |
| 合规边界 | 不提供 Cookie 窃取、验证码绕过、付费/私密/DRM 内容下载入口        |

## 12. 关键风险与处理方式

| 风险             | 影响              | 处理方式                                        |
| ---------------- | ----------------- | ----------------------------------------------- |
| 前后端 DTO 漂移  | 页面字段错乱      | 以 `contracts` 为准，前端类型从契约同步         |
| 任务轮询过频     | UI 卡顿或资源浪费 | 运行中 1 秒轮询，结束后停止；后期再评估事件推送 |
| sidecar 启动失败 | 用户无法下载      | 顶部状态明确提示，提供重启入口和错误详情        |
| Tauri 权限过大   | 安全面扩大        | capabilities 最小化，只开放必要能力             |
| 文件路径处理不当 | 路径安全问题      | 文件路径由后端/Tauri 返回，前端不拼接系统路径   |
| MVP 范围膨胀     | 延期              | 只交付单链接、抖音/快手、任务状态、文件打开     |
| 复杂后台提前实现 | 维护成本升高      | 后期页面按版本创建，不做假入口和空组件          |
