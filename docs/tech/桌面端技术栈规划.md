# 桌面端技术栈规划

版本：V1.1  
日期：2026-04-28

> 阶段 4 更新（2026-04-30）：旧自研 parser 和旧 runtime 路线已退出当前代码和打包链路。当前桌面下载主链路是 Vue -> Tauri/Rust `engine_rpc` facade -> Python `vd-engine` -> `yt-dlp`。

## 1. 产品形态结论

本项目后续目标是“大而全的视频平台爬虫软件”，但部署形态不是服务器系统，而是 Windows/macOS 本地桌面端软件。

推荐产品形态：

```text
Tauri 桌面壳
  + Vue 3 管理型前端
  + Rust EngineProcessManager
  + Python vd-engine / yt-dlp 下载引擎
  + 本地文件系统存储
```

一句话结论：

> 用 Tauri + Vue 做桌面 UI，用 Rust facade 管理本地任务和文件路径，用 Python + yt-dlp 做下载核心，不部署远程服务器。
>
> Python 下载引擎后续随桌面安装包一起分发；用户双击桌面应用后由 Tauri/Rust 自动调用，不要求用户手动启动服务。

| 状态管理      | Pinia                                       | 全局状态，如任务筛选、设置、用户偏好       |

| 请求/异步状态 | TanStack Query for Vue                      | 管理本地引擎查询、缓存、刷新               |
| 图表          | ECharts                                     | 工作台统计、趋势图、平台成功率             |
| 本地 facade | Tauri 2 / Rust | `engine_rpc`、任务状态、文件路径校验 |

| Python 包 | `engine-python` / `vd-engine` | sidecar CLI 入口 |

| 打包 | Tauri Bundle + `vd-engine(.exe)` | 生成 Windows/macOS 安装包 |

### 4.1 后期功能技术覆盖矩阵

该技术栈先服务单链接下载 MVP，后期再按真实需求扩展“大而全的视频平台爬虫软件”能力。

| 后期功能       | 技术支撑                                      | 说明                                                         |
| -------------- | --------------------------------------------- | ------------------------------------------------------------ |
| 多平台适配     | 优先复用 `yt-dlp` extractor，必要时另设适配层 | 不在 MVP 中扩展旧 HTML 解析器                       |
| 单视频下载     | Rust facade + Python `vd-engine` + `yt-dlp`   | 当前主链路，前端仍通过 `engine_rpc` 调用                     |
| 作者主页采集   | 后续采集源模型 + 平台能力封装                 | 等单链接下载稳定后再设计                                     |
| 合集/列表采集  | 后续采集源模型 + 任务队列                     | 不在 MVP 提前建空模块                                        |
| 话题/标签采集  | 后续调度系统                                  | 适合周期或增量采集，后期再评估                               |
| 关键词搜索采集 | 后续独立采集源类型                            | 不影响当前下载闭环                                           |
| 批量链接导入   | Vue 文件导入 + Rust/Python 任务创建           | 前端导入，后端校验、去重、建任务                             |
| 下载队列       | Rust 有界任务状态 + 后续持久化                | MVP 只保留当前会话任务；暂停、恢复、重试后续再做             |
| 并发限流       | Rust Semaphore / Python 进程并发限制          | 防止单机网络和平台请求过密                                   |
| 内容库         | 后续本地数据库或索引                          | 本地保存视频、作者、标签、文件关系                           |
| 内容检索       | 后续本地索引                                  | 先简单查询，全文检索后期再做                                 |
| 去重           | 平台 ID + URL + 文件 Hash                     | 兼顾采集前去重和下载后文件去重                               |
| 去水印         | `yt-dlp` best-effort + 后期 FFmpeg sidecar    | MVP 不做画面级水印修复                                       |
| HLS/m3u8       | `yt-dlp` 处理，复杂媒体后处理交给 FFmpeg      | 不自研分片下载器                                             |
| 动态页面解析   | 优先交给 `yt-dlp`，必要时再评估浏览器方案     | 不为了“可能需要”提前引入 Playwright                          |
| 文件管理       | 本地文件系统 + 后续文件记录                   | 支持文件校验、丢失检测、重新下载、清理                       |
| 统计看板       | 后续本地任务记录 + ECharts                    | 当前 MVP 不承诺跨重启历史统计                                |
| 平台健康监控   | 任务日志 + 平台错误码统计                     | 判断某个平台解析是否异常                                     |
| 授权账号管理   | 本地加密存储 + 显式用户配置                   | 用户主动添加授权，不窃取浏览器 Cookie                        |
| 审计日志       | 后续本地审计记录                              | 记录删除文件、批量任务、配置变更等高风险操作                 |
| 本地配置中心   | Tauri/Rust `settings.json`，后续可迁移数据库  | MVP 不依赖旧 `system_config`                            |
| 桌面打包       | Tauri sidecar + `vd-engine(.exe)`             | 前端、Python 下载引擎、可选 FFmpeg 一起分发                  |

### 4.2 后期依赖引入原则

| 阶段 | 原则                                                                        |
| ---- | --------------------------------------------------------------------------- |
| MVP  | 只引入 Tauri、Vue、Rust facade、Python `yt-dlp`、Element Plus 等基础依赖    |
| V1.x | 按需增加本地任务持久化、ECharts、文件 Hash、下载队列等稳定能力             |
| V2.x | 只有在功能确实需要时再评估 FFmpeg、浏览器自动化、全文检索、复杂调度         |
| 禁止 | 不因“未来可能需要”提前引入 Redis、Kafka、Elasticsearch、分布式调度          |

结论：

> 当前主链路保持 Rust + Python + `yt-dlp`。后期平台化能力按真实需求扩展，不提前恢复旧自研 parser 路线。

## 5. 推荐架构

### 5.1 总体架构

```text
┌─────────────────────────────────────────────┐
│                 桌面应用                     │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │      Vue 3 + Element Plus 前端         │  │
│  │  下载页 / 设置 / 当前会话任务状态       │  │
│  └───────────────────────────────────────┘  │
│                    │                        │
│                    │ invoke('engine_rpc')    │
│                    ▼                        │
│  ┌───────────────────────────────────────┐  │
│  │        Tauri 2 / Rust facade           │  │
│  │  窗口 / 文件选择 / 通知 / 任务状态      │  │
│  └───────────────────────────────────────┘  │
│                    │                        │
│                    │ Python CLI + stdout     │
│                    ▼                        │
│  ┌───────────────────────────────────────┐  │
│  │        Python vd-engine + yt-dlp       │  │
│  │  平台解析 / 下载 / 进度事件 / 错误映射  │  │
│  └───────────────────────────────────────┘  │
│                    │                        │
│        ┌───────────┴───────────┐            │
│        ▼                       ▼            │
│   settings.json              本地下载目录     │
└─────────────────────────────────────────────┘
```

### 5.2 进程模型

| 进程                  | 说明                             |
| --------------------- | -------------------------------- |
| Tauri 主进程          | 管理窗口、系统 API、启动本地引擎 |
| WebView 前端进程      | Vue 页面运行环境                 |
| Python 下载引擎进程     | 负责 `yt-dlp` 下载、进度事件和错误映射 |
| FFmpeg 子进程         | 可选，仅处理 HLS/媒体转换时启动  |
| Playwright 浏览器进程 | 可选，仅动态页面解析时启动       |

这个设计的好处：

| 优点            | 说明                                           |
| --------------- | ---------------------------------------------- |
| 不需要服务器    | 所有能力都在本机运行                           |
| UI 和爬虫解耦   | 前端崩溃不直接破坏爬虫核心设计                 |
| 下载生态可复用 | 平台解析和下载交给 `yt-dlp`，避免自研 parser          |
| 打包可控        | Tauri 负责桌面安装包，Python sidecar 后续独立打包 |
| 后续可扩展      | 后期如果需要服务端化，先复用 JSON-RPC 契约和下载引擎边界 |

### 5.3 启动与生命周期模型

桌面应用启动后，后端引擎应由 Tauri 主进程统一管理，不让用户手动启动。

```text
用户双击应用
  ↓
Tauri 主进程启动
  ↓
Vue 前端窗口加载
  ↓
前端通过 engine.healthCheck 查询 Rust facade
  ↓
创建下载任务时 Rust 启动 Python vd-engine
  ↓
Python 输出 JSON 事件，Rust 更新当前会话任务状态
```

| 生命周期事件 | 处理方式 |
|---|---|
| 应用启动 | Tauri/Rust facade 就绪，读取本地 `settings.json` |
| 前端查询 | 通过 Tauri command 调用 `engine_rpc` |
| 任务创建 | Rust 校验参数并启动 Python `vd-engine` |
| 任务运行中 | Rust 根据 Python stdout JSON 事件更新内存任务状态 |
| 下载失败 | Rust 映射错误码，前端展示明确失败原因 |
| 应用关闭 | 当前任务进程随应用结束；跨重启历史记录后续设计 |
| 下次启动 | 旧 `taskId` 不恢复，查询返回 `TASK_NOT_FOUND` 属于预期 |

原则：

- Vue 前端不直接管理 Python 进程。
- Tauri/Rust 主进程负责下载 facade、健康检查和文件路径校验。
- Python 引擎不暴露公网服务，不要求用户理解“后端服务”。

## 7. 后端本地引擎技术规划

### 7.1 当前技术选择

| 技术 | 选择 | 原因 |
| ---- | ---- | ---- |
| 桌面主进程 | Tauri 2 / Rust | 管理窗口、文件系统、通知和 sidecar 生命周期 |
| RPC facade | Rust `engine_rpc` command | 前端保持 JSON-RPC envelope，Rust 负责方法路由和参数校验 |
| 下载核心 | Python `vd-engine` | 封装下载参数、输出 stdout JSON 事件，便于独立测试 |

| 任务状态 | Rust 进程内 `HashMap` | MVP 足够；跨重启历史记录后续再设计 |

| 打包产物 | `vd-engine(.exe)` sidecar | 阶段 3 先复制已有可执行文件，阶段 4 完善免 Python 环境打包 |

### 7.2 旧引擎处理

| 范围 | 当前定位 |
| ---- | -------- |
| 旧 stdio engine | 已删除，不再作为桌面端 sidecar |
| 旧平台 HTML parser | 已删除，不再作为下载核心扩展 |
| 旧 SQLite/Flyway 方案 | 已删除；当前 MVP 使用 Rust 内存任务表和 `settings.json` |
| 旧打包产物 / runtime | 不进入当前 Tauri 主打包链路 |

结论：

> 当前后端本地引擎是 Rust facade + Python `vd-engine`。

## 8. 前后端通信方案

### 8.1 推荐：Tauri command + JSON-RPC envelope

前端只调用 Tauri command，不直接管理 Python 进程。Rust facade 解析 JSON-RPC envelope，再按方法调用本地逻辑或启动 Python `vd-engine`。

```text
Vue 前端
  ↓ invoke('engine_rpc')
Tauri/Rust EngineProcessManager
  ↓ Python CLI 参数
Python vd-engine
  ↓ stdout JSON 事件
Rust 更新当前会话任务状态
```

| 优点 | 说明 |
| ---- | ---- |
| 无需端口 | 不启动 localhost 服务 |
| 安全边界清晰 | 外部程序不能直接访问内部 API |
| 前端契约稳定 | 前端仍使用 `download.createTask` / `download.getTask` 等 JSON-RPC 方法 |
| 实现简单 | Rust 维护任务状态，Python 专注下载 |

### 8.2 Python CLI 事件边界

Python `vd-engine` 不承载通用 JSON-RPC server，只负责一次下载任务：

```text
vd-engine --url <url> --output-dir <dir> --remove-watermark <bool> --allow-fallback <bool>
```

stdout 按行输出进度、完成、失败等 JSON 事件；Rust 读取事件并转换为 `DownloadTask`。

### 8.3 不推荐：localhost HTTP

| 问题 | 说明 |
| ---- | ---- |
| 端口管理复杂 | 本地端口冲突和访问控制没有必要 |
| 安全面更大 | 其他本机进程可能访问 API |
| 产品形态不匹配 | 当前是桌面工具，不是本地 Web 服务 |

建议：

> 正式桌面架构收敛到 Tauri command；除非临时排查问题，不引入 localhost HTTP。

## 9. 本地存储规划

### 9.1 MVP 存储边界

| 数据 | 存储位置 | 说明 |
| ---- | -------- | ---- |
| 当前任务状态 | Rust 进程内 `HashMap` | 应用重启后旧 `taskId` 失效属于预期 |
| 当前页面最近任务 | 前端 session / Pinia | 只服务本次运行，不做复杂历史库 |
| 下载设置 | Tauri/Rust `settings.json` | 下载目录、并发、去水印偏好 |
| 下载文件 | 用户选择的本地目录 | Rust 校验路径后再开放给前端 |
| 日志 | 用户数据目录 | 记录下载失败、引擎异常等排障信息 |

MVP 不迁移旧任务数据库，也不承诺跨重启历史记录。历史库、内容库、审计日志后续按真实需求重新设计。

## 10. 打包与安装

### 9.1 推荐打包结论

推荐采用：

```text
Tauri Bundle
  + Vue 静态资源
  + Python vd-engine(.exe)
  + 可选 FFmpeg sidecar
```

用户安装后只看到一个桌面应用。阶段 4 已通过 PyInstaller 输出 `vd-engine.exe`，并在 Tauri build 前复制到 `src-tauri/binaries/`。

### 9.2 Python 下载引擎随桌面端分发方式

| 组成 | 打包方式 | 说明 |
|---|---|---|
| Python 下载引擎 | `vd-engine(.exe)` | `engine-python` 的 console script 或后续打包产物 |
| Tauri sidecar | `binaries/vd-engine(.exe)` | Tauri 负责随应用分发和启动 |
| 设置文件 | 用户配置目录下的 `settings.json` | 不放安装目录，避免升级覆盖 |
| 下载目录 | 用户可配置目录 | 默认放用户视频目录 |

推荐启动方式：

```text
Tauri/Rust EngineProcessManager
  ↓
启动 binaries/vd-engine(.exe)
  ↓
Python 引擎调用 yt-dlp 并输出 JSON 事件
```

### 9.3 Python sidecar 打包边界

| 阶段 | 方案 | 说明 |
| ---- | ---- | ---- |
| 阶段 3 | 复制已有 `vd-engine(.exe)` | `scripts/copy-sidecar.sh` 从虚拟环境或 `VD_ENGINE_BINARY` 指定路径复制 |
| 阶段 4 | PyInstaller 单文件打包 | `scripts/build-python-engine.ps1` 输出并复制稳定 `vd-engine.exe` |
| 后期 | 可选 FFmpeg sidecar | 只有需要媒体后处理时再随包分发 |

当前不再比较旧打包路线；发布链路统一收敛到 Python sidecar。

### 9.4 Tauri sidecar 配置方向

当前采用 Tauri `bundle.resources` 分发 Python 下载引擎，由 Rust 使用资源目录路径启动。

`tauri.conf.json` 当前配置：

```json
{
  "bundle": {
    "resources": ["binaries/**/*"]
  }
}
```

权限配置方向：

```json
{
  "permissions": [
    "core:default",
    {
      "identifier": "shell:allow-execute",
      "allow": [
        {
          "name": "binaries/vd-engine",
          "sidecar": true
        }
      ]
    }
  ]
}
```

实际项目中建议由 Tauri Rust 主进程封装启动命令，而不是让 Vue 页面直接调用 sidecar。

### 9.5 平台安装包

| 平台 | 方案 |
| ---- | ---- |
| Windows | Tauri 生成 `.msi` 或 `.exe` 安装包 |
| macOS | Tauri 生成 `.dmg` 或 `.app` |
| Python 下载引擎 | 阶段 4 打包为 `vd-engine(.exe)` |
| FFmpeg | 后期作为可选 sidecar 分发 |

### 9.6 安装包内外目录划分

安装目录只放程序和运行时，用户数据必须放用户数据目录。

```text
安装目录/
  app executable
  resources/
    frontend assets
    binaries/
      vd-engine(.exe)

用户数据目录/
  logs/
  settings.json
  temp/
  downloads/
```

不要把设置、日志和下载文件放到安装目录。升级应用时不能覆盖用户数据。

### 9.7 注意点

| 问题 | 处理方式 |
| ---- | -------- |
| 用户未安装 Python | 阶段 4 输出独立 `vd-engine(.exe)`，不要求用户安装 Python |
| Python 引擎异常退出 | Tauri/Rust 捕获失败事件，任务进入 `FAILED` 并展示错误 |
| 下载中关闭应用 | MVP 提示任务可能中断；跨重启恢复后续再做 |
| macOS 签名 | 后期发布需要代码签名和 notarization |
| Windows 杀软误报 | 安装包签名、减少可疑行为 |
| 应用升级 | 升级时保留用户数据目录 |
| FFmpeg 分发 | 作为可选 sidecar，注意平台架构差异 |

## 11. 可选能力技术选择

### 11.1 动态页面解析

| 方案 | 建议 |
| ---- | ---- |
| `yt-dlp` extractor | 当前优先，避免自研页面解析 |
| 浏览器自动化 | 只有公开内容必须动态渲染且 `yt-dlp` 不支持时再评估 |
| 手写 HTML/脚本抽取 | 不作为当前主链路，维护成本高且容易失效 |

### 11.2 HLS/m3u8 下载

| 方案 | 建议 |
| ---- | ---- |
| `yt-dlp` | 当前优先处理下载和格式选择 |
| FFmpeg sidecar | 推荐用于合并、转封装、复杂媒体处理 |
| 自研分片下载器 | 不优先，容易把 MVP 拖成媒体框架 |

### 11.3 周期任务调度

| 阶段 | 技术 |
| ---- | ---- |
| MVP | 不做周期任务 |
| 后期 | 先用简单本地调度，复杂周期任务再评估专用调度器 |

### 11.4 全文检索

| 阶段 | 技术 |
| ---- | ---- |
| 早期 | 本地任务/文件记录普通查询 |
| 后期 | 按内容库规模再评估全文索引 |
| 不建议 | 本地桌面端一开始引入 Elasticsearch |

## 12. 不推荐方案

### 12.1 Electron + Node 全家桶

| 问题 | 说明 |
| ---- | ---- |
| 体积大 | Electron 安装包和运行内存明显更高 |
| Node 依赖复杂 | 爬虫生态强，但依赖和安全面更大 |

结论：除非强依赖 Node 生态，否则不推荐。

### 12.2 直接做远程 Web 系统

不符合当前要求。用户明确需要 Windows/macOS 桌面软件，不需要服务器。

## 15. 最终推荐

| 决策项       | 推荐                                                 |
| ------------ | ---------------------------------------------------- |
| 是否做服务器 | 不做远程服务器                                       |
| 桌面外壳     | Tauri 2                                              |
| 前端         | Vue 3 + TypeScript + Element Plus                    |
| 后端         | Tauri/Rust facade + Python `vd-engine` / `yt-dlp` |
| 通信         | Tauri `invoke('engine_rpc')` + JSON-RPC envelope |
| 数据库       | MVP 不使用数据库；当前为 settings.json + 会话任务状态 |
| 打包         | Tauri Bundle + `vd-engine(.exe)`                  |
| 动态解析     | 交给 `yt-dlp` extractor；不继续扩展自研 parser    |
| 媒体处理     | FFmpeg sidecar 作为后期可选模块                    |

这套方案的核心优点是：

1. 不需要服务器，符合桌面端定位。
2. UI 现代，适合做复杂管理台。
3. 下载核心复用 `yt-dlp`，后续平台维护成本低。
4. MVP 不背负 SQLite 历史记录，跨重启任务历史后续按真实需求设计。
5. Tauri 比 Electron 更轻，安装包和运行内存更适合工具软件。
6. 旧自研解析路线已删除，避免后续继续走错方向。
