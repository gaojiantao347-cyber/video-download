# 项目目录结构规划

## 1. 目标

本项目定位为 Windows/macOS 桌面端视频下载工具。当前主链路：

```text
Tauri 桌面壳
  + Vue 3 前端
  + Rust EngineProcessManager
  + Python vd-engine / yt-dlp 下载引擎
  + 本地文件系统存储
```

目录结构只保留当前能支撑 MVP 和近期扩展的模块，避免空目录和过期实现污染项目。

## 2. 当前总目录结构

```text
video-download/
  docs/                         # 产品、技术、接口文档
    product/
    tech/
    api/

  contracts/                    # 前后端协议契约
    schemas/                    # JSON Schema / DTO 结构定义
    rpc/                        # JSON-RPC 方法定义
    errors/                     # 错误码、错误语义、前端展示策略

  apps/
    desktop-ui/                 # Vue 3 + Tauri 桌面端工程
      src/                      # Vue 前端源码
      src-tauri/                # Rust 主进程、engine_rpc facade、打包配置
        binaries/               # 打包前复制进来的 sidecar
          vd-engine.exe         # Windows Python 下载引擎产物

  engine-python/                # 当前 Python 下载引擎
    pyproject.toml              # Python 包配置，提供 vd-engine console script
    src/video_download_engine/  # CLI、yt-dlp 封装、协议和错误映射
    tests/                      # Python 引擎测试
    dist/                       # PyInstaller 输出，构建产物
    build/                      # PyInstaller 临时产物

  scripts/                      # 构建、打包、复制 sidecar
    build-python-engine.ps1     # Windows 构建 vd-engine.exe
    package-desktop.ps1         # Windows 桌面发布入口
    copy-sidecar.sh             # Bash 环境复制已有 sidecar
    package-desktop.sh          # Bash 环境桌面打包入口

  tools/                        # 开发辅助工具，不放业务逻辑
```

## 3. 核心目录职责

| 目录 | 职责 |
|---|---|
| `apps/desktop-ui/` | 前端页面、Tauri 集成、桌面交互、状态展示 |
| `apps/desktop-ui/src-tauri/` | Rust facade、任务状态、文件路径校验、sidecar 启动 |
| `engine-python/` | `yt-dlp` 下载、进度事件、错误映射、Python 测试 |
| `contracts/` | RPC、DTO、错误码的共享边界 |
| `docs/` | 产品和技术方案说明 |
| `scripts/` | 构建、打包、复制 sidecar，不写业务逻辑 |

## 4. Tauri 目录结构

```text
apps/desktop-ui/src-tauri/
  tauri.conf.json               # Tauri 打包配置，resources 包含 binaries/**/*
  Cargo.toml
  capabilities/
    default.json

  binaries/
    vd-engine.exe               # Windows 发布时必须存在
    ffmpeg                      # 后期需要媒体处理时再加入

  src/
    main.rs
    engine_process.rs           # engine_rpc facade、任务状态、Python CLI 启动
    rpc_bridge.rs
    file_system.rs
    app_paths.rs
```

关键边界：

- Vue 前端不直接启动 Python 进程。
- Rust 主进程负责 `engine_rpc` facade 和 sidecar 生命周期。
- Python 引擎通过 CLI 参数和 stdout JSON 事件与 Rust 通信。
- 发布包必须内置 `vd-engine.exe`，不要求用户手动安装 Python。

## 5. engine-python 目录结构

```text
engine-python/
  pyproject.toml
  src/video_download_engine/
    __init__.py
    cli.py
    downloader.py
    protocol.py
    errors.py
    progress.py
  tests/
```

职责边界：

| 文件 | 职责 |
|---|---|
| `cli.py` | 解析命令行参数，输出 JSON 事件 |
| `downloader.py` | 调用 `yt-dlp` 下载视频 |
| `protocol.py` | 定义请求、进度、成功、失败结构 |
| `errors.py` | 参数校验和异常映射 |
| `progress.py` | 转换 `yt-dlp` 进度为统一事件 |

## 6. 打包与构建目录

Windows 发布链路：

```text
engine-python/src/video_download_engine/cli.py
  -> scripts/build-python-engine.ps1
  -> engine-python/dist/vd-engine.exe
  -> apps/desktop-ui/src-tauri/binaries/vd-engine.exe
  -> scripts/package-desktop.ps1
  -> Tauri 安装包
```

脚本职责：

| 脚本 | 职责 |
|---|---|
| `scripts/build-python-engine.ps1` | 创建/复用 `.venv`，安装打包依赖，构建并复制 `vd-engine.exe` |
| `scripts/package-desktop.ps1` | 先构建 sidecar，再执行 Tauri build |
| `scripts/copy-sidecar.sh` | Bash 环境复制已有 `vd-engine(.exe)` 到 Tauri binaries |
| `scripts/package-desktop.sh` | Bash 环境执行复制和 Tauri build |

## 7. 用户运行时数据目录

运行时数据不进入源码目录。

| 平台 | 用户数据目录 |
|---|---|
| Windows | `%APPDATA%/video-download/` |
| macOS | `~/Library/Application Support/video-download/` |

建议结构：

```text
video-download/
  downloads/
  logs/
  cache/
  config/
    settings.json
```

## 8. 团队协作边界

| 团队 | 主目录 | 主要职责 |
|---|---|---|
| 前端 / 桌面端团队 | `apps/desktop-ui/` | Vue 页面、Tauri 集成、桌面交互、状态展示、用户设置 |
| 后端 / 本地引擎团队 | `engine-python/`、`apps/desktop-ui/src-tauri/` | 下载核心、Rust facade、任务状态、文件路径校验 |
| 双方共同维护 | `contracts/` | DTO、JSON-RPC 方法、错误码、协议版本 |
| 产品和架构共同维护 | `docs/` | 功能规划、技术规划、接口说明 |

接口变更流程：

```text
先改 contracts/
  -> Rust facade / Python 引擎同步实现
  -> 前端同步 TypeScript 类型和 API client
  -> 更新 docs/api/ 人读说明
```

## 9. 结论

当前推荐 monorepo：

```text
video-download/
  docs/
  contracts/
  apps/desktop-ui/
  engine-python/
  scripts/
  tools/
```

这套结构足够支撑 MVP：前端、Rust facade、Python 下载引擎和协议边界清晰；后续扩展任务历史、批量下载、内容库或 FFmpeg 后处理时，再按真实需求新增模块。
