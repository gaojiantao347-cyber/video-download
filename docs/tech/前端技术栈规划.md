# 前端技术栈规划

版本：V1.0  
日期：2026-04-28

## 1. 文档定位

本文档面向前端 / 桌面端开发团队，说明本项目 Windows/macOS 桌面软件的前端技术栈、开发工具、职责边界、目录结构、构建方式和与 Tauri/Rust + Python 下载引擎的协作方式。

项目整体定位：

```text
Tauri 桌面壳
  + Vue 3 管理型前端
  + Rust EngineProcessManager
  + Python vd-engine / yt-dlp 下载引擎
  + 本地文件系统存储
```

前端团队负责：

| 职责           | 说明                                                 |
| -------------- | ---------------------------------------------------- |
| 桌面 UI        | 工作台、任务、队列、内容库、设置等页面               |
| 桌面容器集成   | Tauri 窗口、菜单、托盘、通知、文件选择               |
| 前后端调用封装 | 通过 Tauri command 调用 Rust `engine_rpc` facade       |
| 状态展示       | 任务状态、下载进度、平台健康、错误提示               |
| 交互安全       | 文件删除、批量任务、配置变更等高风险操作二次确认     |
| 打包协作       | 接入后端 sidecar 产物，生成 Windows/macOS 桌面安装包 |

前端团队不负责：

| 不负责项            | 说明                           |
| ------------------- | ------------------------------ |
| 平台解析和下载      | 由 Python `yt-dlp` 下载引擎处理 |
| 视频下载核心        | 由 Python 下载引擎实现          |
| Rust 任务状态       | 由 Tauri/Rust facade 维护       |
| 去水印下载策略      | 由本地下载引擎按 best-effort 处理 |
| 本地文件路径校验    | 由 Tauri/Rust 主进程维护        |

## 2. 前端推荐技术栈

| 分类      | 技术                    | 用途                     | 选择原因                                     |
| --------- | ----------------------- | ------------------------ | -------------------------------------------- |
| 桌面容器  | Tauri 2                 | Windows/macOS 桌面应用壳 | 比 Electron 更轻，支持 sidecar，适合本地工具 |
| 前端框架  | Vue 3                   | 页面和组件开发           | 管理台类页面效率高                           |
| 语言      | TypeScript              | 类型约束                 | DTO、任务状态、平台枚举需要类型安全          |
| 构建工具  | Vite                    | 开发与构建               | 快，生态成熟                                 |
| UI 组件库 | Element Plus            | 表格、表单、弹窗、分页   | 后台管理 UI 成本低                           |
| 路由      | Vue Router              | 页面路由                 | 工作台、任务、内容库等多页面必需             |
| 状态管理  | Pinia                   | 全局状态                 | 比 Vuex 简洁，适合 Vue 3                     |
| 异步状态  | TanStack Query for Vue  | 查询、缓存、轮询、刷新   | 适合任务状态、队列、统计数据查询             |
| 图表      | ECharts                 | 统计图表                 | 工作台、平台成功率、存储趋势                 |
| 工具函数  | VueUse                  | 常用组合式工具           | 减少手写样板代码                             |
| 样式      | CSS Variables + SCSS    | 主题和样式组织           | 易维护，可做主题切换                         |
| 测试      | Vitest + Vue Test Utils | 单元测试                 | 测组件和组合式函数                           |
| E2E       | Playwright Test，可选   | 桌面核心流程测试         | 后期验证关键用户路径                         |
| 代码规范  | ESLint + Prettier       | 格式和质量               | 团队协作必需                                 |
| 包管理    | npm                    | 依赖管理                 | 快，磁盘占用低，适合 monorepo                |

## 4. 前端架构分层

```text
apps/desktop-ui/
  src/
    app/                 # 应用入口、全局初始化
    layouts/             # 主布局、侧边栏、顶部栏
    router/              # Vue Router
    pages/               # 页面级组件
    components/          # 通用组件
    features/            # 按业务功能组织的模块
    stores/              # Pinia store
    queries/             # TanStack Query 封装
    api/                 # 调用 Tauri command 的 API 封装
    events/              # 本地引擎事件订阅
    types/               # 前后端共享 DTO 类型定义
    utils/               # 工具函数
    assets/              # 静态资源
  src-tauri/
    tauri.conf.json      # Tauri 配置
    capabilities/        # 权限配置
    src/                 # Tauri Rust command 和 sidecar 生命周期管理
```

推荐按 `features` 组织复杂业务：

```text
features/
  dashboard/
  platforms/
  crawl-sources/
  crawl-tasks/
  download-queue/
  content-library/
  authors/
  file-manager/
  settings/
  audit-log/
```

## 7. 前后端通信边界

### 7.1 推荐调用链

```text
Vue 页面
  ↓
api/*.ts 封装
  ↓
Tauri invoke('engine_rpc')
  ↓
Tauri Rust EngineProcessManager
  ↓
Python CLI + stdout JSON 事件
  ↓
yt-dlp 下载核心
```

前端原则：

| 原则 | 说明 |
|---|---|
| 不直接管理 Python 进程 | 下载引擎生命周期由 Tauri/Rust 主进程管理 |
| 不直接读写本地配置文件 | 设置通过 `settings.*` RPC 获取和保存 |
| 不拼业务规则 | 任务状态流转、平台解析、去水印策略由本地引擎决定 |
| DTO 类型统一 | 前后端共享接口字段定义，避免手写不一致 |
| 错误码统一展示 | 前端只做错误码到用户文案映射 |

### 7.2 前端 API 封装建议

```text
api/
  engineClient.ts        # Tauri command 调用封装
  platformApi.ts
  crawlSourceApi.ts
  crawlTaskApi.ts
  downloadQueueApi.ts
  videoApi.ts
  authorApi.ts
  fileApi.ts
  settingsApi.ts
  auditApi.ts
```

## 8. Tauri 职责边界

| Tauri 能力   | 前端团队负责内容                              |
| ------------ | --------------------------------------------- |
| 窗口管理     | 主窗口、最小化、关闭确认                      |
| 菜单/托盘    | 后期可做后台运行入口                          |
| 文件选择     | 下载目录选择、导入文件选择                    |
| 系统通知     | 任务完成、任务失败、磁盘不足提醒              |
| Sidecar 集成 | 接入后端提供的 Python `vd-engine` 下载引擎    |
| 权限配置     | 只开放必要权限，避免滥开 shell 和文件系统权限 |

注意：

- Tauri 主进程可以用 Rust 写少量胶水代码。
- 不要把业务逻辑写进 Rust 层。
- Rust 层只负责桌面能力、`engine_rpc` facade 和 Python 下载进程生命周期。

## 9. 前端构建与交付

| 阶段     | 命令/产物                                                  | 说明                        |
| -------- | ---------------------------------------------------------- | --------------------------- |
| 开发     | `npm dev`                                                 | 启动 Vite 前端开发服务      |
| 桌面开发 | `npm tauri dev`                                           | 启动 Tauri 桌面开发模式     |
| 前端构建 | `npm build`                                               | 生成 Vue 静态资源           |
| 桌面打包 | `npm tauri build`                                         | 打包 Windows/macOS 桌面应用 |
| 接入后端 | 依赖后端产出的 `vd-engine(.exe)` sidecar | 前后端构建流水线需要衔接    |

## 10. 前端质量要求

| 要求              | 说明                                           |
| ----------------- | ---------------------------------------------- |
| TypeScript strict | 新代码必须有类型约束                           |
| 页面组件瘦身      | 页面负责组合，业务状态放到 feature/store/query |
| API 统一封装      | 禁止页面里直接写 Tauri invoke 细节             |
| 高风险操作确认    | 删除文件、批量取消、修改目录必须确认           |
| 状态展示一致      | 任务状态、下载状态、去水印状态统一组件         |
| 错误提示明确      | 展示后端错误码对应的可理解文案                 |
| 不写平台业务解析  | 平台规则留给 Python/yt-dlp 下载引擎             |

## 11. 不推荐的前端方案

| 方案                     | 不推荐原因                                                      |
| ------------------------ | --------------------------------------------------------------- |
| Electron                 | 体积和内存更重，当前没有强依赖 Node 桌面生态                    |
| React + 大量状态库       | 可以做，但当前团队若无强偏好，Vue + Element Plus 管理台效率更高 |
| 页面直接调 localhost API | 正式架构应通过 Tauri command，不暴露本地服务端口                |
| Vue 页面直接启动 sidecar | 生命周期应该由 Tauri 主进程管理                                 |
