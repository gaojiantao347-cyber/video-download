# 后端技术栈规划

版本：V1.1  
日期：2026-04-30

## 1. 文档定位

本项目后端是桌面应用内的本地下载引擎，不是远程服务器。

```text
Tauri 桌面应用
  -> invoke('engine_rpc')
  -> Rust EngineProcessManager
  -> Python vd-engine sidecar
  -> yt-dlp
  -> 本地下载目录
```

## 2. 推荐技术栈

| 分类 | 技术 | 用途 | 选择原因 |
|---|---|---|---|
| 桌面 bridge | Tauri 2 / Rust | JSON-RPC facade、任务状态、文件路径校验 | 已在桌面端主进程落地，启动快，边界清晰 |
| 下载核心 | Python + `yt-dlp` | 平台解析、视频下载、进度事件 | 复用成熟生态，避免自研平台解析 |
| Python 包管理 | `pyproject.toml` + `.venv` | 本地开发、测试、构建 `vd-engine` | 标准、轻量、可脚本化 |
| Windows 打包 | PyInstaller | 生成免安装 Python 的 `vd-engine.exe` | 单文件 sidecar，接入 Tauri 简单 |
| 前端通信 | Tauri `invoke('engine_rpc')` + JSON-RPC envelope | 保持前端调用稳定 | 前端不直接管理进程 |
| 任务状态 | Rust 进程内 `HashMap` | MVP 当前会话任务状态 | KISS；历史记录后续再设计 |
| 设置存储 | Tauri/Rust 写 `settings.json` | 下载目录、并发、去水印偏好 | 本地桌面应用足够用 |
| 桌面打包 | Tauri bundle resources | 分发 `binaries/vd-engine.exe` | 用户无需手动配置开发环境 |

## 4. 核心接口

| 接口 / 方法 | 作用 |
|---|---|
| `engine.healthCheck` | 返回 Rust facade 运行状态和任务存储类型 |
| `engine.getVersion` | 返回当前 bridge 版本 |
| `settings.get` / `settings.update` | 读写下载目录和偏好设置 |
| `download.createTask` | 校验参数、创建任务、启动 Python sidecar |
| `download.getTask` | 查询当前会话任务状态和进度 |
| `download.getFile` | 任务成功后返回本地文件路径 |
| Python stdout JSON | 上报 progress、completed、failed 事件 |

## 5. 打包与运行

### 5.1 开发态

开发态可直接运行 Python 源码：

```text
Rust -> python -m video_download_engine.cli download ...
```

也可以设置：

```powershell
$env:PYTHON_ENGINE_PATH="D:\path\to\vd-engine.exe"
```

### 5.2 发布态

发布态使用 PyInstaller 产物：

```text
engine-python/dist/vd-engine.exe
  -> apps/desktop-ui/src-tauri/binaries/vd-engine.exe
  -> Tauri bundle resources
```

构建命令：

```powershell
.\scripts\build-python-engine.ps1
.\scripts\package-desktop.ps1
```

## 6. 后期能力支撑方式

| 后期功能 | 后端实现方式 |
|---|---|
| 多平台下载 | 优先复用 `yt-dlp` extractor，不足时再单独评估 |
| 批量链接 | 前端导入后逐条创建任务；后端增加队列和限流 |
| 下载历史 | 需要时再设计本地任务数据库 |
| 内容库 | 后续独立设计视频、作者、文件索引 |
| 去水印 | `yt-dlp` best-effort；媒体后处理后续按需引入 FFmpeg |
| Cookie | 用户显式选择本地 Cookie 文件，不读取或上传隐私数据 |
| 审计日志 | 删除文件、批量任务、配置变更等高风险操作再引入 |

## 7. 不推荐方案

| 方案 | 不推荐原因 |
|---|---|
| 本地 Web 服务 | 增加端口、生命周期、安全边界复杂度 |
| Redis / Kafka | 本地桌面应用过度设计 |
| ORM / 数据库优先 | MVP 当前只需要会话任务状态 |
| 浏览器自动化起步 | 维护成本高，先依赖 `yt-dlp` |
| 媒体处理起步 | 增加体积和故障面，先下载最佳可用格式 |

## 8. 最终结论

当前后端技术栈固定为：

```text
Rust facade + Python vd-engine + yt-dlp + Tauri bundle resources
```

项目自身只维护桌面交互、任务状态、下载目录、错误展示和打包体验；平台解析和下载能力交给 `yt-dlp` 生态。
