# 后端开发计划：Python + yt-dlp 本地下载引擎

日期：2026-04-30  
适用模块：`engine-python`、`apps/desktop-ui/src-tauri`、`contracts`、`scripts`

## 1. 当前目标

后端不是远程服务，而是随 Tauri 桌面应用分发的本地下载能力：

```text
Vue 前端
  -> Tauri invoke('engine_rpc')
  -> Rust EngineProcessManager
  -> Python vd-engine
  -> yt-dlp
  -> 本地下载目录
```

当前阶段只追求一个结果：用户输入公开视频链接后，桌面应用能下载到本地，并能展示进度、成功、失败原因。

## 2. MVP 范围

| 模块 | 路径 | 职责 |
|---|---|---|
| Python 下载引擎 | `engine-python/` | 调用 `yt-dlp` 下载视频，输出 stdout JSON 事件 |
| Rust facade | `apps/desktop-ui/src-tauri/src/engine_process.rs` | 参数校验、任务状态、启动 sidecar、读取事件 |
| 前端协议封装 | `apps/desktop-ui/src/api/engineClient.ts` | 统一调用 `engine_rpc` JSON-RPC envelope |
| 契约 | `contracts/` | 记录 RPC、DTO、错误码边界 |
| 构建脚本 | `scripts/` | 构建 `vd-engine.exe` 并打包桌面应用 |

不做：远程 Web 服务、复杂任务调度、数据库迁移、平台签名逆向、权限绕过、DRM/付费/私密内容下载。

## 4. 当前开发重点

| 优先级 | 工作 | 输出 |
|---|---|---|
| P0 | Windows sidecar 打包 | `scripts/build-python-engine.ps1` 生成 `vd-engine.exe` |
| P0 | 桌面发布脚本 | `scripts/package-desktop.ps1` 串联 sidecar 与 Tauri build |
| P0 | 错误提示 | sidecar 缺失、环境变量错误、启动失败时给出明确原因 |
| P1 | 下载失败映射 | 保持 Python 错误码到前端错误文案稳定 |
| P1 | 真实链接回归 | 用公开视频链接验证下载成功和失败提示 |
| P2 | 任务历史 | 如确实需要，再设计本地持久化 |
| P2 | Cookie 文件 | 仅支持用户显式提供的本地 Cookie 文件 |

## 5. 构建与验证

打包机需要 Python 3.11+、Node.js、Rust/Tauri 构建环境。最终用户不需要这些开发环境。

```powershell
cd "D:\Users\gaojiantao\project\video-download"
python -m pytest "engine-python\tests"
.\scripts\build-python-engine.ps1
.\apps\desktop-ui\src-tauri\binaries\vd-engine.exe --help
.\scripts\package-desktop.ps1
```

执行策略受限时使用：

```powershell
powershell -ExecutionPolicy Bypass -File ".\scripts\build-python-engine.ps1"
powershell -ExecutionPolicy Bypass -File ".\scripts\package-desktop.ps1"
```

## 6. 质量原则

| 原则 | 要求 |
|---|---|
| KISS | Python 引擎只做下载相关能力，Rust 只做 facade 和任务状态 |
| YAGNI | 不提前引入数据库、队列、浏览器自动化、媒体后处理 |
| DRY | 错误码、DTO、RPC 方法以 `contracts/` 为边界 |
| 安全 | Cookie 只读本地文件，不上传、不打印敏感内容 |
| 可发布 | `vd-engine.exe` 必须进入 `apps/desktop-ui/src-tauri/binaries/` 并随 Tauri bundle 分发 |
